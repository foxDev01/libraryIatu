# Project instructions

## Проверки перед пушем — только локально

GitHub Actions (CI/CD) в этом проекте **удалены и не возвращаются**: все проверки запускаются
локально перед каждым push в main. Посадочные команды (порядок как в `.githooks/pre-push`):

```bash
composer lint        # Pint --test + PHPStan (larastan, уровень 6)
php artisan test     # PHPUnit на SQLite :memory:
npm run lint         # ESLint
npm run typecheck    # tsc --noEmit
npm run build        # сборка фронтенда
```

- Хук уже активирован через `git config core.hooksPath .githooks`; после свежего клона его
  нужно включить заново — скажи об этом пользователю, если пуш отклонён.
- Не оставляй репозиторий в состоянии «проверки не прогонены»: перед каждым push прогони полный
  набор; если что-то не проходит — чини, а не пропускай.
- Не добавляй workflow-файлы, Dependabot, CI-бейджи и прочую удалённую автоматизацию.

## Тесты: что и как писать

- Основной вид — **интеграционные тесты бэкенда** (Feature-тесты PHPUnit, SQLite `:memory:`):
  HTTP-контракт, авторизация, права доступа, состояния БД. Один тест — один сценарий,
  понятные русские названия (`test_a_user_...`).
- E2E — только критические сценарии (вход/регистрация, просмотр книг, CRUD вопросов),
  короткие и суперпростые. Не имитируй браузерные пайплайны Laravel — это Integration, не E2E.
- Юнит-тесты — минимум: по умолчанию не пишутся. Пиши только если есть чистая логика без HTTP/БД.
- Запрещено: placeholder-тесты (`assertTrue(true)`), тесты фреймворка (health check, роутинг Laravel),
  дублирующие друг друга fixture-сценарии. Каждый тест должен фиксировать поведение продукта;
  иначе — не писать.
- Смердженные проверки в один тест — норма, если фикстура общая; не размножай тесты ради счётчика.

## Стек и конвенции

- PHP 8.5, Laravel 13, SQLite; React 17 + TypeScript (MUI 4), Vite 7.
- Локаль по умолчанию `ru`: ошибки валидации и UI-сообщения — на русском.
- API: GET только для чтения, изменения через `POST` / `PUT` / `DELETE` (CSRF-защита SPA Sanctum).
- Не коммитить: `libraryiatu.sql` (персональные данные!), `.env`, `database/*.sqlite`,
  `public/build`, `vendor`, `node_modules`, IDE-каталоги.
- Модели Eloquent держи типизированными (larastan уровень 6 должен проходить без ignore-комментариев).
