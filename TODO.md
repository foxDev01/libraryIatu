- [x] **Восстановление пароля** — готово

    троттлинг 6/мин) зарегистрированы вручную в `routes/api.php`.
  - Страницы SPA `/forgot-password` и `/reset-password?token=…&email=…`
    (`resources/js/Application/components/Auth/`).
  - Ссылка в письме ведёт на страницу SPA (`ResetPassword::createUrlUsing`); тексты письма
    переведены через `resources/lang/ru.json`, ответ на запрос всегда нейтральный —
    существование email не раскрывается (`App\Http\Responses\PasswordResetLinkSentResponse`).
  - Для разработки почта идёт в `log`-mailer; для эксплуатации понадобится реальный SMTP
    (см. раздел «Эксплуатация / деплой»).

    адрес ссылки в письмах SPA и панели Filament, успешный сброс, одноразовость токена,
    битый токен/слабый пароль/без токена, троттлинг).

- [x] **Файлы книг на сервере, а не только внешние ссылки** — готово
  - Хранение в **приватном** диске `local` (`storage/app/private/books`): файлы не отдаются
    напрямую и `php artisan storage:link` не нужен (безопаснее, чем план с `public`).
  - Загрузка через Filament (`FileUpload` в форме книги, 50 МБ, PDF/EPUB/DOC(X)/RTF/TXT/FB2/DJVU),
    в таблице колонка «Хранение»: файл на сервере или внешняя ссылка.
  - Отдача через `GET /api/books/{id}/download` с проверкой учебной группы (403 чужой группе),
    имя файла — название книги; для внешних ссылок — 302 редирект.
  - Книги из дампа остаются с внешним `link`; SPA различает сценарии по флагу `has_file`
    (внутренний путь `file_path` в API не отдаётся).
  - Очистка: файл удаляется вместе с книгой и при замене; перед удалением книги
    снимаются связи из `group_books`/`discipline_books`.
  - Тесты: `BookUploadTest` (загрузка через панель, «нужен файл или ссылка»),
    `BookDownloadTest` (своя группа, чужая группа — 403, гость — 401, редирект по внешней
    ссылке, 404 если файла нет на диске, удаление книги вместе с файлом и связями),
    `BookTest` (контракт JSON: есть `has_file`, нет `file_path`).
